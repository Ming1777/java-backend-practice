## 一分钟项目介绍

我在学习过程中做了一个用户中心项目，使用 Spring Boot、MyBatis、MySQL 和 Redis，支持用户注册、登录退出、信息查询以及账号状态管理。注册时使用 BCrypt 对密码做单向哈希，登录时验证输入密码是否匹配。

我重点练习了用户详情缓存：查询时先读 Redis，未命中再查询 MySQL，并缓存结果；对于不存在的用户，使用短期空值标记减少重复回源。修改用户状态后，先更新数据库，再删除对应缓存。

项目接入 Swagger UI 查看和调用接口，使用 SLF4J 日志记录业务流程与异常。目前还在完善权限、异常 HTTP 状态映射和部署等内容。

## 二叉树入门

可运行代码：[BinaryTreeDemo.java](../src/day21/BinaryTreeDemo.java)。在 IDEA 中运行这个类的 `main` 方法。

```text
       10
      /  \
     20   30
    /
   40
```

- 根节点是整棵树中没有父节点的节点，这里是 10。
- 40 的父节点是 20；给 20 添加孩子不会改变整棵树的根。
- 每个节点最多有两个孩子；没有孩子的节点叫叶子，这里是 30 和 40。
- `value` 保存数字，`left` 和 `right` 保存左右孩子的引用；没有对应孩子时，该引用为 `null`。
- `root.right.value` 为 30；`root.left.left.value` 为 40。

前序遍历顺序是“当前节点 → 整个左子树 → 整个右子树”，本例为：

```text
10 20 40 30
```

`preorder` 在方法内部再次调用自己，这叫递归。每次调用处理传进来的那个节点；遇到 `null` 就返回上一层调用，上一层再继续自己的下一条语句。因此先走完 20、40 所在的左子树，最后才访问 30。

本例的前序遍历时间复杂度是 O(n)，因为每个节点访问一次；递归调用栈空间是 O(h)，h 为树高，退化成一条链时为 O(n)。这些是后续巩固点，先理解访问顺序。

## 今日八股收尾

旧题：为什么修改用户后删除 Redis 缓存？

数据库中的用户信息发生变化后，旧缓存可能过时。项目在数据库更新成功后删除对应缓存，下次查询未命中时读取数据库并重新建立缓存。禁用用户会被现有 `status = 1` 查询条件过滤，查无结果时写入短期空值标记。

新题：为什么把项目分成 Controller、Service、Mapper？

Controller 处理 HTTP 请求与响应，Service 组织业务规则，Mapper 负责数据库访问。职责清楚后，接口形式变化、业务规则变化和 SQL 变化更容易分别修改，也便于复用业务逻辑、编写测试和定位问题。分层本身并不自动提升查询速度。

补充复习：BCrypt 用于单向密码哈希；HTTP 状态与业务 code 按各自定义判断；日志记录不会自动执行补救逻辑。
